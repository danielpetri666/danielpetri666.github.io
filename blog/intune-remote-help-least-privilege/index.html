Intune Remote Help: Build a Help Desk Role You Can Explain

Build two Intune Remote Help roles around attended Windows support and prove their boundaries.

The Problem

The support request says the user can’t find a setting. The support role can take control of the desktop. That permission will still be there when the next ticket arrives.

In the EPM blog, I scoped elevation to one build of a maintenance utility. Remote Help puts a different decision on the help desk: who can help this user, and what can they do once the session starts? I’ll show how two scoped Intune roles shape an attended Remote Help session on enrolled Windows devices. Intune EPM blog · Remote Help planning and RBAC

Licensing

I used Intune Suite licenses for this blog. Microsoft 365 E3 also includes Remote Help. All participants need the entitlement. Intune licensing and planning · Remote Help prerequisites

If your help desk already uses TeamViewer or another remote support tool, pick a Windows ticket you handle every week. For attended Windows support within the same tenant, see if Remote Help can close that ticket with the license you already have. A missing Outlook setting is a good place to start.

Implementation

How Remote Help decides what a helper can do

For an attended session, the helper and sharer sign in to the same tenant. The scope groups in the helper’s Intune role assignment determine who the helper can assist. The role permissions determine which actions the helper can request. The sharer then decides whether to allow the request. Remote Help planning and RBAC

That gives the help desk three checks to make when a session fails. Is this person in scope? Can the helper request this mode? Did the user allow it? Each question points to a different part of the setup.

To help someone on a managed Windows device, start from the device in the Intune admin center. Intune sends a notification to the device, and the user opens Remote Help from it. There’s no security code to pass back and forth. The device needs the Intune Management Extension to receive the notification. Start a Remote Help session · Remote Help prerequisites

You can also start directly in the Remote Help app. The helper generates a security code, and the sharer enters it in the app.

The two entry points have different access requirements. From the Intune admin center, the helper needs Managed devices > Read to open the target device record and Remote Tasks > Offer remote assistance to launch the action. Keep device visibility within the support scope. With a security code, the helper can work entirely in the Remote Help app. The code flow still uses Intune RBAC for Remote Help. I verified it before granting either helper Managed devices > Read. Intune RBAC permissions · Remote Help role requirements

Build roles from work the help desk actually does

A user with a missing Outlook option is a good view-only case. A user who needs someone to change a series of application settings may need full control. A task that prompts for UAC raises another question: whose credentials will be entered, and should the help desk perform that operation remotely?

Both roles omit Elevation. Keep helpers out of overlapping role assignments when checking which grant takes effect. Remote Help role requirements

Then review the role assignment. The member group is the set of people acting as helpers. The scope groups define which users or devices they can help. Document both in the same change request. A least-privilege role with a huge scope is still a huge scope.

How to verify the two roles

I enabled Remote Help in a test tenant and used three enrolled Windows VMs with the Remote Help app and three licensed standard-user accounts. Each assignment’s Admin Groups contained a security group with one helper. Both assignments used the same Scope (Groups) group, with only the test sharer as a member. I used the Default scope tag. Intune role assignments

For the portal runs, both custom roles also had Managed devices > Read and Organization > Read. The second permission came out of the notification troubleshooting below.

  1. As the view-only helper, open the in-scope device in Intune. Start a remote assistance session, choose Remote Help, and select Initiate attended control. Open the app from the portal. Have the sharer open it from the notification. Check the mode picker, request screen sharing, and have the sharer approve it.
  2. Keep the same sharer and VM. Repeat the portal flow as the full-control helper, request Take full control, and have the sharer approve it. Check the control state on both clients.
  3. To test scope in the app, first connect the full-control helper to the in-scope sharer using a security code. Start a fresh attempt with the same helper and have an account outside the sharer group enter the new code. I used the view-only helper account on its own VM for that last attempt.

Troubleshooting and reporting

When Intune stays on Sending notification

Both scoped helpers could open the device and start the action, but the portal stayed on Sending notification. My lab admin could send a notification to the same VM. After I added Organization > Read to the custom roles, both helpers could start attended sessions from Intune and the sharer got the Windows notification.

Microsoft describes Organization > Read as access to tenant settings. Its Remote Help role guidance lists the Remote Help permissions without naming that tenant read permission. The before-and-after result above is what I observed in this tenant. The app’s security-code flow had already worked with the original roles. Intune RBAC permissions · Remote Help role requirements

The first troubleshooting pass

If the helper can’t start the session, walk the assignment backward. Verify the helper account, its role membership, the scope groups and the target endpoint’s state. Check the Remote Help client and tenant configuration before giving the helper another role. Adding Help Desk Operator can make the test pass by granting the access you were trying to prove unnecessary.

Record where the attempt stopped. A disabled mode, a permissions error before the prompt, and a sharer choosing Decline each give the next person a different place to start.

What the session report can tell you

On a later check, Remote Help sessions showed four records matching the completed sessions: screen sharing and full control started from Intune, and the same two modes started with a security code. I found no row matching the out-of-scope attempt at that check. The permissions error in the app shows where that attempt stopped.

Microsoft documents 30-day retention for session metadata. The report can help establish who connected and when. If you need to know which setting changed, look for an audit trail on the endpoint or in the application. Remote Help monitoring and reports

Known Limitations

The examples cover attended Windows support. Both roles omitted the Elevation permission. The Remote Help sessions report does not show use of Windows elevation. Remote Help monitoring and reports

Windows unattended control uses a separate permission and requires a supported physical, corporate-owned device. Virtual machines are outside that support boundary. Remote Help platform requirements

Security Considerations

Keep the help-desk boundary reviewable

I’d give the team a short role table with tickets it can handle and an escalation path for help requiring full control or elevation. Review role assignments during handovers. If an incident requires a higher grant, capture who requested it, which targets it covers and when it comes off.

The useful question after rollout is the one you can ask on an ordinary Monday. Who can help this employee right now, what can they request, and which evidence will still be available when somebody reviews the ticket?
